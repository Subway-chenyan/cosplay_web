# 浏览状态与导航约定

当前架构：React Router 管理页面，Redux 保存服务端结果，页面本地状态保存输入草稿。此前页码、筛选、标签和滚动分别由 Redux、useState、hash 与直接 scrollTo 控制，导致刷新丢条件、后退错标签及分页数据叠加。

## 本次调整

- 首页、社团、比赛列表以 URL 为浏览状态来源；社团使用 q、province、page。更换条件回第一页，翻页保留条件。
- 比赛页每次请求 12 条，默认替换上一页；明确 append 才追加。赛程标签从 #schedule 派生，支持前进后退。
- RouteScrollManager 在路由外统一管理滚动。每个 history entry 保存独立位置；sessionStorage 最多保留 100 条。后退、前进、刷新恢复位置；新页面从顶部开始；主动筛选和翻页使用 state.scrollTarget 定位内容区域。
- 异步页面用 data-route-loading 标记等待状态，MutationObserver/ResizeObserver 等待内容可定位；用户滚轮、触摸或滚动按键立即取消自动定位。恢复最多等待 15 秒，存储不可用不影响导航。
- 请求取消和 requestId 校验防止社团、比赛旧响应覆盖新响应。
- 普通登录保留受保护页面的完整回跳地址；直接打开视频详情时，返回按钮可回首页。
- 分页适配换行、标识当前页、加载期间禁用操作，修复两个省略号被去重的问题。
- 地图直接使用省份统计，不再逐省串行预取社团；点击省份后由列表请求对应页。

## 验证与后续边界

自动化覆盖历史滚动恢复、用户主动中止定位、分页按钮、异常页码、筛选请求参数、分页替换与响应竞争。Vitest 只扫描当前 src，避免嵌套 worktree 的重复 React 干扰测试。

本次重点覆盖视频、社团、比赛的主要浏览路径。论坛筛选仍由 Redux 保存；智能检索模式、比赛详情“加载更多”后的累计页数尚未成为 URL 状态，因此不能保证刷新重建这些额外状态。QQ 第三方登录的回跳流程未在本次改动中扩展。后续可逐步接入相同的 URL 状态约定。
